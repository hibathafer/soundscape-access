Spec · Technical BlueprintSoundscape Access

Status: Approved
PRD said “what it does.” Now we know how: Flutter/Dart (her language), bundled YAMNet inside the phone, a behavior analyzer instead of direction detection, a Door-only Knock confirmation, and an Android foreground-service attempt with an honest fallback.

How This Works, In Plain Language

One Flutter program (Dart) on the phone, five parts talking to each other:

  1. The ears — keeps listening during the session, hands over short audio slices.
  2. The name-giver — bundled YAMNet scores 521 labels on-device and maps them to five categories or Unknown. Scores do not guarantee correct identification.
  3. The behavior reader — measures onset, repetition, and fade from the level stream. Direction was removed after device tests found no reliable signal.
  4. The brain — start/stop, known and Unknown artwork, optional vibration, and an attempt at background capture with a foreground fallback.
  5. The face — a center pulse describing sound strength and behavior, plus swipeable category artwork.

Audio inference runs on-device. The app has no server, account, API key, or cloud-classification integration; ambient audio is not uploaded by the app.

Architecture — Data Flow

Flow: Audio Capture (mic 16 kHz) → Sound Classifier (YAMNet → 5 categories) and Sound Behavior Analyzer (onset, repetition, fade) → Session Controller (rules, events, fallback) → Flash + Bubbles UI → Vibration Service (toggle only). App Shell commands feed the controller.

The Core Journey Through the System

PRD ref: prd.md > The Core Journey — traced through the pieces.

  1. Open app → App Shell renders the one light screen from fresh in-memory state.
  2. First start → gentle mic explanation → system dialog. Denied → friendly message + settings.
  3. Start pressed → controller sets session on → toast “Working now” → capture streams slices.
  4. Leaves the app → Android foreground service (type: microphone), started from foreground; refused/killed → fallback: app stays in front.
  5. Each slice → two paths: classifier → category/confidence (weak → unknown) · behavior analyzer → onset/repetition/strength.
  6. Events merge → center pulse describes strength and behavior + category artwork appears; two sounds → two events.
  7. Vibration toggle on → one buzz per event. Sound stops → levels drop → pulse fades out.
  8. Stop → session off → capture, service, vibration all end.

Components (each with its PRD home)

🎧 Audio Capture Service — prd.md > Sound capture and classification

Keeps the mic open for the session; streams 16 kHz mono PCM slices; owns the permission flow (gentle line → system dialog). Stops on Stop/kill. Files: lib/audio/.

🧠 Sound Classifier — prd.md > Unknown sounds

assets/model/yamnet_mediapipe.tflite + 521 labels from assets/model/labels.txt; 15,600 mono samples at 16 kHz per inference. Normal category threshold is 0.35. Door-only fallback: Knock label 353 ≥ 0.12 and greater than Tap label 354 in at least two of the last three completed windows. This heuristic does not guarantee against false positives. Files: lib/classify/.

Sound Behavior Analyzer — prd.md > Sound pulse

Measures onset, repetition, and fade from the level stream. Direction was removed after the documented four-round device investigation found no reliable signal.

⚙ Session Controller — prd.md > Starting and stopping / leaving the app

Owns session state, toast, events, vibration toggle, background attempt (FGS type microphone, started from foreground) + approved fallback. Files: lib/session/.

✨ Flash + Bubbles UI — prd.md > Sound-type bubbles / Simultaneous sounds

Consumes events: center pulse (strength/behavior) + swipeable category artwork (neutral “?” for Unknown). Two events render independently. Files: lib/ui/.

📳 Vibration Service — prd.md > Vibration (manual, simple)

One buzz per event while the toggle is ON; no patterns; VIBRATE permission (normal). Files: lib/session/vibration_service.dart.

External Services & Dependencies

No external runtime services. The app has no server, account, cloud API, or API-key integration. Audio inference uses the bundled YAMNet model locally. Flutter packages and Android OS APIs are dependencies.

Important Failure Modes

DENIEDMicrophone permission refused

Friendly message + route to settings (prd.md); no crash.

QUIET / UNSURESilence or unclassifiable sound

Silence → nothing; a completed sound inference with no category above threshold → neutral “?” artwork. A skipped/busy inference is not treated as Unknown.

BACKGROUND KILLEDXiaomi MIUI/HyperOS kills the service

Approved fallback: session continues with the app in front; Autostart/battery exemption documented as setup.

DIRECTION REMOVEDNo reliable directional signal found

Direction was removed after four device tests; the current pulse describes sound behavior, not source location.

MODEL LOAD FAILUREBundled model missing or incompatible

Classification falls back to Unknown while the pulse may continue. The bundled file exists; execution on every device is not guaranteed.

What Was Simplified and Why

  • On-device YAMNet instead of a cloud API — ambient audio is not uploaded by the app.
  • No persistence instead of settings/history — restart = fresh session (PRD).
  • One screen, no navigation — the product is one loop.
  • Bundled labeled samples for the demo instead of depending on live traffic on demand — the live path stays real and primary.
  • Simple vibration instead of patterns — her cut.
