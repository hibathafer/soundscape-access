Spec · Technical BlueprintSoundscape Access

Status: Approved
PRD said “what it does.” Now we know how: Flutter/Dart (her language), YAMNet inside the phone (free · offline · private), two microphones for direction — tested on her Xiaomi 12T Pro first, honest fallback if it misbehaves, Android 14 foreground service for leaving the app, zero servers and $0.

How This Works, In Plain Language

One Flutter program (Dart) on the phone, five parts talking to each other:

  1. The ears — keeps listening during the session, hands over short audio slices.
  2. The name-giver — YAMNet, a tiny AI model inside the phone: “car / speech / door / alarm / birds / don’t know.” Nothing leaves the device.
  3. The compass — compares the phone’s two microphones to guess the side. Tested on the real phone first; if it misbehaves we adjust the plan together — never fake it.
  4. The brain — start/stop, the rules (known → colored bubble, unknown → white “?”, vibration only when toggled), and the attempt to keep listening after the user leaves the app.
  5. The face — the flash that ignites on the sound’s side and fades away, plus swipeable bubbles and the two buttons.

Why this shape: everything on the phone — no servers, no accounts, no internet, no keys, no cost; it starts instantly and records cleanly for the demo.

Architecture — Data Flow

Flow: Audio Capture (mic 16 kHz) → Sound Classifier (YAMNet → 5 categories) and Direction Estimator (2-mic levels, research first) → Session Controller (rules, events, fallback) → Flash + Bubbles UI → Vibration Service (toggle only). App Shell commands feed the controller.

The Core Journey Through the System

PRD ref: prd.md > The Core Journey — traced through the pieces.

  1. Open app → App Shell renders the one dark screen from fresh in-memory state.
  2. First start → gentle mic explanation → system dialog. Denied → friendly message + settings.
  3. Start pressed → controller sets session on → toast “Working now” → capture streams slices.
  4. Leaves the app → Android foreground service (type: microphone), started from foreground; refused/killed → fallback: app stays in front.
  5. Each slice → two paths: classifier → category/confidence (weak → unknown) · direction estimator → side/strength.
  6. Events merge → flash ignites on the sound’s side with the proximity color + icon bubble appears; two sounds → two events.
  7. Vibration toggle on → one buzz per event. Source recedes → levels drop → flash fades out.
  8. Stop → session off → capture, service, vibration all end.

Where It Runs & How Someone Tries It

  • Runtime: Android app — test device Xiaomi 12T Pro · Android 14 (SDK 34) (Flutter + ADB verified on the machine; device connects via USB debugging). Emulator only for pure UI — direction/classification tests run on the real phone.
  • Dev start: flutter run · Demo/APK: flutter build apk → install → open Soundscape Access → Start → record screen.
  • Submission: short demo video + public GitHub repo required; deployment optional, not chosen (revisit in 6-ship).
  • Xiaomi setup notes: USB debugging on; for background capture allow Autostart + battery-optimization exemption (MIUI/HyperOS kills background services).

Components (each with its PRD home)

🎧 Audio Capture Service — prd.md > Sound capture and classification

Keeps the mic open for the session; streams 16 kHz mono PCM slices; owns the permission flow (gentle line → system dialog). Stops on Stop/kill. Files: lib/audio/.

🧠 Sound Classifier — prd.md > Unknown sounds

TFLite model + labels from assets/model/; slice → scores → exactly five categories; below confidence threshold → unknown (threshold tuned in the build — implementation detail). Files: lib/classify/.

🧭 Direction Estimator — prd.md > Directional flash RESEARCH FIRST

Two-mic level comparison (top vs bottom on the test device) → side + strength. Build step 1 verifies individual mic access + a repeatable level difference from a known side. Two mics on one axis bias top/bottom; if unusable → plan-revision conversation — never faked. Files: lib/direction/ + Kotlin bridge.

⚙ Session Controller — prd.md > Starting and stopping / leaving the app

Owns session state, toast, events, vibration toggle, background attempt (FGS type microphone, started from foreground) + approved fallback. Files: lib/session/.

✨ Flash + Bubbles UI — prd.md > Sound-type bubbles / Simultaneous sounds

Consumes events: directional edge flash (side/strength/color, fades with level) + swipeable bubbles (icon; white “?” unknown). Two events render independently. Files: lib/ui/.

📳 Vibration Service — prd.md > Vibration (manual, simple)

One buzz per event while the toggle is ON; no patterns; VIBRATE permission (normal). Files: lib/session/vibration_service.dart.

External Services & Dependencies

None external — $0, no keys, no rate limits. Bundled only: Flutter SDK (verified installed), tflite_flutter, YAMNet model asset (Apache-2.0 — .tflite availability unverified), vibration, Android OS APIs.

Important Failure Modes

DENIEDMicrophone permission refused

Friendly message + route to settings (prd.md); no crash.

QUIET / UNSURESilence or unclassifiable sound

Silence → nothing; a real sound with no confident name → white “?” bubble, direction still shown.

BACKGROUND KILLEDXiaomi MIUI/HyperOS kills the service

Approved fallback: session continues with the app in front; Autostart/battery exemption documented as setup.

DIRECTION UNUSABLEIndividual mics not selectable / no level difference

Plan-revision conversation with the learner; degraded options decided together — kernel never faked.

MODEL MISSINGNo ready .tflite YAMNet file

Convert from TF Hub ourselves or swap an equally small model — decide in build step 1, before UI work.

What Was Simplified and Why

  • On-device YAMNet instead of a cloud API — free/offline/private; cloud stays a later enhancement only if the core works and time remains.
  • No persistence instead of settings/history — restart = fresh session (PRD).
  • One screen, no navigation — the product is one loop.
  • Bundled labeled samples for the demo instead of depending on live traffic on demand — the live path stays real and primary.
  • Simple vibration instead of patterns — her cut.
